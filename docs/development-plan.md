# 开发计划与交付标准

## 1. 开发策略

完整目标是第一人称开放世界深林冒险。实施采用“先验证可玩性，再扩展世界，再提高内容生产效率”的顺序。

两条工作线并行但不互相阻塞：

- 游戏线：Godot 灰盒、操作、战斗、任务、存档。
- 内容线：Blender 资产、森林生成器、导入和优化。

AI 接入晚于确定性的 Blender 生成器，避免调试时无法区分模型输出问题和生成器问题。

## 2. 阶段划分

### M0：工程基础

交付：

- Godot 工程和目录结构。
- 输入映射、设置和日志。
- 第一人称移动原型。
- 自动构建基础。
- 文档与代码规范。

退出条件：

- Windows 开发构建可在全新环境启动。
- 键鼠移动、暂停和退出正常。
- 严重错误写入日志。

### M1：灰盒可玩链路

交付：

- 营地、树林、守林站灰盒。
- 交互、物品、背包和任务。
- 基础存档。
- 一条可完成任务链。

退出条件：

- “营地出发—拾取保险丝—修复设备—返回”可完整游玩。
- 保存后重启能恢复关键状态。
- 不存在阻断进度的问题。

### M2：探索与战斗垂直切片

交付：

- 1 km × 1 km 区域。
- 世界 Chunk 加载。
- 弓箭战斗与两类敌人。
- 一个主任务、两个世界事件、一个隐藏地点。
- 昼夜、天气和环境音频。

退出条件：

- 首次玩家 20～30 分钟完成主线。
- 可偏离主路并获得有效奖励。
- 推荐配置 1080p 接近稳定 60 FPS。
- Chunk 切换不丢失任务和敌人状态。

### M3：程序化森林管线

交付：

- SceneSpec 与 Schema。
- 植被、岩石与营地道具的**资产网格**生成（含材质、LOD、碰撞代理）。
- 资产 GLB、manifest 和预览图。
- Godot 导入检查器。
- 按资产粒度的局部重生成。

退出条件：

- 相同版本、seed 和输入产生相同清单（逐字节一致）。
- 重新生成单个资产不波及其他资产，也不覆盖人工任务对象。
- 生成结果通过几何和性能预算检查。
- 运行时确实装载管线产出的资产，而不是 `PropKit` 的程序化网格。

> **职责边界见 [`forest-pipeline-spec.md`](./forest-pipeline-spec.md) §2。**
> 管线生产资产，运行时生产地形与撒点——两者不重复。
> 里程碑拆分为 M3-1 ~ M3-4，见 [`forest-pipeline-spec.md`](./forest-pipeline-spec.md) §10。

### M4：内容替换与打磨

交付：

- 灰盒替换为正式或中等精度资产。
- 地标、路径、任务和敌人完整整合。
- UI、音频、可访问性和设置。
- 性能与稳定性优化。

退出条件：

- 完整垂直切片通过内部测试。
- 无 P0/P1 缺陷。
- 连续运行 60 分钟无崩溃或严重内存增长。
- 最低配置达到 30 FPS 目标。

### M5：开放世界扩展

交付：

- 第二生态区域。
- 区域间旅行和进度门槛。
- 更完整的成长、制作和敌人体系。
- 世界任务与动态事件工具。

退出条件：

- 新区域可以复用生产管线。
- 跨区域存档、任务和快速旅行稳定。
- 内容生产速度达到可持续水平后再决定完整地图规模。

## 3. 优先级

### P0

- 第一人称控制。
- 交互与任务。
- 存档。
- Chunk 加载。
- 基础战斗。
- 性能监控。
- Windows 构建。

### P1

- 天气与昼夜。
- 动态事件。
- 程序化森林生成。
- 制作与成长。
- 辅助功能。

### P2

- 自然语言生成 SceneSpec。
- 更多生态区。
- 高级动物生态。
- 配音和复杂演出。
- Mod 或编辑器能力。

## 4. 完成定义

一项功能只有同时满足以下条件才算完成：

- 功能行为符合设计文档。
- 错误路径有处理。
- 关键状态可保存和加载。
- 有必要的自动测试或明确人工用例。
- 性能未突破预算。
- 键鼠操作和 UI 提示完整。
- 文档已同步更新。
- Windows 开发构建验证通过。

## 5. 缺陷等级

| 等级 | 定义 | 示例 |
|---|---|---|
| P0 | 无法构建、启动或继续游戏 | 崩溃、存档损坏 |
| P1 | 核心功能失效且无绕行 | 主任务卡死、玩家坠落 |
| P2 | 明显影响体验但可绕行 | 敌人卡住、加载闪现 |
| P3 | 轻微表现问题 | 小范围穿模、文字问题 |

垂直切片发布前必须清除所有 P0/P1 缺陷。

## 6. 风险清单

| 风险 | 应对 |
|---|---|
| 开放世界范围失控 | 按区域生产，先完成垂直切片 |
| 森林重复感强 | 地标、生态分层、人工路径和变体组合 |
| Godot 大场景性能不足 | Chunk、HLOD、MultiMesh、预算监控 |
| 程序化结果不可控 | Schema、seed、预览和人工审批 |
| 第一人称战斗手感差 | 早期灰盒测试，不等正式美术 |
| AI 生成不稳定 | AI 只输出 SceneSpec，生成器保持确定性 |
| 存档随版本损坏 | 版本化格式、迁移测试和备份 |
| 单人开发工作量过大 | 锁定 P0，减少敌人和系统种类 |
