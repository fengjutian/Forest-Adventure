### 分块世界

| 模块 | 职责 |
|---|---|
| `scripts/world/terrain_field.gd` | **全局高度真相**：`height_at(x, z)` 叠加基础起伏、大尺度地貌、北侧主山脊、溪谷下切与营地平整；顶点色按高度/坡度/区域着色 |
| `scripts/world/chunked_world.gd` | 流式加载：以玩家所在区块为锚点，按同心环排队生成 / 卸载区块；持有材质与树木网格缓存；把世界种子和改动区块接入存档 |
| `scripts/world/world_chunk.gd` | 单个区块：41 × 41 地形网格（1.6 m 一格）、凹多边形碰撞、按全局格点撒植被（松树 5 变体 / 桦树 2 变体 / 枯木 / 岩石 / 灌木 / 地被） |
| `scripts/world/camp_site.gd` | 营地装配：人工地标 → 贴地 → 水面动画；营地不参与分块，常驻世界 |
| `scripts/world/camp_builder.gd` | 人工地标：木屋、物资棚、发电机、训练靶场、倒木、路牌、帐篷、灯柱、柴堆、木桶、溪流水面 |
| `scripts/world/prop_kit.gd` | 程序化网格与材质库（顶点色即反照率），正式美术资产到位后只替换这里 |

加载半径：

| 距离 | 内容 |
|---:|---|
| 0～2 圈（≤128 m） | 地形 + 碰撞 + 完整植被（含地被） |
| 3～5 圈（≤320 m） | 地形 + 稀疏乔木 |
| 6～7 圈（≤448 m） | 仅地形（距离雾遮住边缘） |
| > 7 圈 | 卸载 |

> **跨块无缝靠的是「只有一个高度函数」，不是缝合算法。** 相邻区块在边界顶点上采样同一个
> `TerrainField.height_at()`，世界坐标相同则高度必然相同；区块外还多采一圈顶点用于算法线，
> 光照接缝也不会露。区块网格、碰撞、植被落地全部走这一个函数。
>
> **同一个 seed 必得同一个世界**：区块随机数由（世界种子, 区块坐标）派生，与加载顺序和方向无关；
> 植被候选点是全局格点，一个格只归属一个区块，密度由跨块共享的低频噪声调制。
> 存档只写 `{seed, 改动过的区块}`，不写整张地图。
>
> **性能**：生成按帧分摊（地形 / 植被 / 碰撞各有队列，共享 3 ms 预算），碰撞单独排队，
> 避免玩家跨区块时一帧内建好几块碰撞。1080p 下 225 块全加载保持 60 FPS；
> 瞬移 23 m / 8 帧的流式压力测试最差帧 14.6 ms。

### 树木

- 每棵树都是独立生成的形态：**5 个松树变体 + 2 个桦树变体**，层数、半径、层间偏移都随 seed 变化，森林里没有两棵完全一样的树
- 混交林：桦树占乔木 22%，另有枯立木、倒木、树桩提供林下层次
- 树冠用顶点着色器**随风轻摆**（`PropKit.swaying_material()`）：高度加权，越高摆得越多；每棵树的相位写在 MultiMesh 实例自定义数据里，整片林子不会齐刷刷一起晃
- 被测层不投影：看不出来却要多走一遍阴影 pass，关掉后每帧三角形数从 1.5M 降到 0.9M

### 画面精度

「画面糊」要分清是分辨率、采样，还是资产精度，三者的代价差一个数量级：

| 层 | 现状 | 代价 |
|---|---|---|
| 渲染分辨率 | 窗口多大就渲多大；2560 × 1440 窗口实测输出 2560 × 1440 | 0 |
| 抗锯齿 | MSAA 4x + 天空抖动去色带（debanding） | 几乎为零 |
| 接触阴影 | SSAO，半径 2.2 m | 1440p 下约 1 ms/帧 |
| 地形网格 | 1.6 m 一格（40 段 / 64 m 区块） | 流式压力测试平均帧 7.56 → 7.78 ms |
| 几何 / 材质 | 树冠 8 段锥、顶点色、无贴图 | **这是美术方向，不是渲染参数** |

- **分辨率不是瓶颈**：`window/stretch/mode="canvas_items"` 只缩放 2D，3D 视口跟随窗口尺寸，
  所以高分辨率屏幕上不会把 1080p 拉大糊掉。
- **MSAA 2x → 4x**：整个场景都是硬边低多边形，斜边最吃采样；这是性价比最高的一档。
- **SSAO**：顶点色材质没有贴图也没有法线细节，物体「贴不贴地」只能靠接触阴影交代。
- **阴影距离保持 60 m**：拉到 110 m 会把同一张阴影贴图摊到更大范围，近处阴影反而变糊 —— 那是降精度，不是提精度。
- **不采用**：TAA（运动时糊，低多边形更明显）、超采样 1.25x（1440p 下约 +50% 帧时间，观感更柔）、
  阴影距离拉远（见上）。

再往上就要动物件本身：树冠加段、地形换贴图、建筑换正式资产，属于 M3/M4 的内容替换。

> 对比工具：`godot --disable-vsync --path game res://tests/capture_quality.tscn` 按档位抓同机位截图
> 并打印帧时间，`tools/quality_compare.py` 把两档裁 1:1 拼成对照图。

### 战斗系统

垂直切片只做**弓箭**这一种主武器和**林狼**一种敌人（`docs/combat-and-progression.md §1、§4`）。

**弓箭**

| 操作 | 效果 |
|---|---|
| 鼠标右键（按住） | 瞄准：视野 75° → 55°，鼠标灵敏度 ×0.45，准星张开 |
| 鼠标左键（按住 → 松开） | 蓄力射击：蓄满 1.1s，基础伤害 32，箭速 16→42 m/s |
| 蓄力 | 持续消耗体力（14/s）；体力不足时蓄得更慢，体力耗尽就完全蓄不满 |
| 发射 | 箭矢从背包扣除，右下角显示余量；射箭产生 1.2s 噪声，会暴露位置 |

- 弓常驻在第一人称画面右下，瞄准时抬到屏幕左侧三分之一，箭尖收拢到准星附近
- 弓是**「人」的动作**而不是一把浮空的弓：左手扣握把、右手捏弦（垂弓时右手自然垂在弓把下方，不跟左手挤一起），双手直接挂在弓身上；蓄力时弓弦折成 V 形、箭随之后移；走路与冲刺有持弓摆动，站定时有呼吸起伏，转视角有惯性滞后
- **两条小臂**：手模只画手，小臂是单独成件（`make_player_forearm`），从画面底边斜插进来给手一个锚点。左手往左下、右手往右下；拉弦手的肘部朝**后下方**——肘部朝前的话小臂会横着掠过画面中段像一根横杆。袖子刻意做得比真人小臂长（0.88 m），必须一直延伸到画面外才不会被看到断口
- 第一人称弓是**独立打光的视图模型**：单独占一层视觉层，太阳与手电都不照它——否则弓背光时是一块黑影、白天又被顶成奶白；木色、皮手套与红色箭羽的取值都是按实机渲染结果反推调出来的
- **视图模型的调色一律用乘系数，不用 `Color.lightened()`**：`lightened()` 是往白色混，混完饱和度就没了，深棕手套会变成一块灰砖。配色深浅按「实机取色 → 反推 albedo」迭代，配套工装是 `res://tests/capture_bow.tscn`
- 玩家有**本体模型**（`PropKit.make_player_body`）：躯干、腰、双腿、靴子。肩线在 1.44 m、低于站立相机 1.62 m，所以平视时身体完全在画面外，低头才看得到胸口和腿，不会再出现「低头一片空洞」。蹲下时整个身体按 Y 压缩，保证相机不会钻进躯干
- 箭矢是**手动积分 + 射线检测**（`Node3D` 而非 `RigidBody3D`）：42 m/s 下物理帧之间会穿过去，手动射线还能精确取命中点判断弱点
- 命中判定取自命中点高度，高于狼的 `weak_point_height` 算弱点，**弱点伤害 ×2**
- 命中敌人扣血并显示命中标记；命中环境则钉在表面 6 秒后消失

**林狼**

- **成群示警**：一只狼进入追逐时，30m 内的同伴一起转入追逐
- **听觉优先**：听觉 22m > 视觉 24m 但触发更直接——听到动静直接扑过来，看到目标先怀疑再确认
- **包围**：不去抢同一个落点，按稳定 ID 派生固定包抄侧，几只狼从不同方向围上来
- **畏火光**：靠近营火 7m 内会绕开
- **对角小跑**：4 条腿按对角步态摆动，速度越快步频越快
- 感知用射线遮挡检查，保证「敌人不能隔墙发现或攻击玩家」；`leash_radius` 之外脱离战斗返回

**伤害模型**：普通伤害 / 弱点伤害（×2）/ 火焰伤害 / 环境伤害。命中后有硬直，生命低于 25% 转入逃跑。

**敌人状态存档**：已击败的敌人通过稳定 ID 记进 `changed_objects`（如 `wolf_01_drop_arrow`），读档后不会复活；绝不使用运行时实例 ID。

> **切片范围裁剪**：文档 §2 有「专注」资源，但 `game-design.md:184` 的切片范围不含专注，
> 因此蓄力消耗改用体力。这是为了在切片范围内自洽，不是对文档的裁决。

## 常用命令

```powershell
# 一条命令启动（自动定位 Godot，必要时先导入资源）
.\tools\run.ps1

# 用 Godot 编辑器打开工程
.\tools\run.ps1 -Editor

# 运行游戏（等价于 tools\run.ps1，但需要自己处理首次导入）
& $env:GODOT_EXE --path game

# 导入资源（新克隆后必须先跑一次，生成全局类缓存）
& $env:GODOT_EXE --headless --path game --import

# 无头冒烟测试（155 项检查）
& $env:GODOT_EXE --headless --path game res://tests/test_smoke.tscn

# 分块世界压力测试（无头，瞬移穿越全图，打印最差帧时间）
& $env:GODOT_EXE --headless --path game res://tests/bench_world.tscn

# 分块世界多机位截图（营地 / 溪谷 / 俯瞰 / 林道 / 山脊）
& $env:GODOT_EXE --path game res://tests/capture_world.tscn

# 抓取渲染帧（需要图形后端，不能 --headless）
& $env:GODOT_EXE --path game res://tests/capture_screenshot.tscn

# 抓取战斗画面（林狼 / 举弓瞄准 / 营地俯视）
& $env:GODOT_EXE --path game res://tests/capture_combat.tscn

# 抓取持弓特写（垂弓 / 举弓蓄力两张，用于调弓的构图与配色）
& $env:GODOT_EXE --path game res://tests/capture_bow.tscn

# 抓取玩家本体（略低头看胸口 / 深度低头看腿 / 蹲下三张）
& $env:GODOT_EXE --path game res://tests/capture_body.tscn

# 画质档位对比（同机位、锁时间与天气，逐档打印帧时间）
& $env:GODOT_EXE --disable-vsync --path game res://tests/capture_quality.tscn

# 完整构建（导入 → 测试 → 导出）；无导出模板时用 -SkipExport
.\tools\build_windows.ps1
.\tools\build_windows.ps1 -SkipExport
```

> **首次运行必须先导入。** Godot 依赖 `.godot/global_script_class_cache.cfg` 解析
> `class_name` 声明的脚本。新克隆的仓库没有这个缓存，直接 `--path game` 会报
> `Identifier "GameLog" not declared in the current scope`。
> `tools\run.ps1` 会自动判断并补做导入；用编辑器打开时 Godot 也会自动导入。

> **鼠标不会被自动锁定。** 启动后光标仍在系统里，屏幕中央提示「点击画面控制视角 · Esc 释放鼠标」。
> 点击画面才进入视角控制，Esc 随时归还鼠标，切到别的程序时也会自动释放。

> **窗口焦点**：启动时游戏会主动把窗口提到前台。如果切到别的窗口再切回来，WASD 会打到那个窗口上，
> 看起来就像「角色不会动」——HUD 会显示「窗口未聚焦 — 点击游戏窗口继续」，点一下游戏窗口即可恢复。

> **按键提示**：进游戏先在右侧弹出按键表，9 秒后自动收起；之后按 H 随时开关，
