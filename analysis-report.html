01

现状快照：现在究竟能跑什么

每一项都在仓库里找得到实现，并已在本机 Godot 4.6 上实际运行（无头测试 + 渲染截图 + 帧时间采样）。数字取自代码常量与运行日志。

分块世界

  • 1,024 m 见方 = 16×16 个 64 m 区块；每块 33×33 顶点（2 m 一格）、2,048 面
  • 地形 7 圈 → 最多 225 块；碰撞 2 圈（25 块）；植被满配 2 圈、稀疏 5 圈
  • 地形 / 植被 / 碰撞各一条队列，地形与植被共享 3 ms 帧预算
  • 启动同步建 3 圈（49 块地形 + 25 块碰撞），之后分帧补齐
  • 单一高度函数 height_at(x,z)：地形、碰撞、植被落地、玩家贴地全靠它

植被与地表

  • 每块最多 13 个 MultiMesh 节点：松树 5 变体、桦树 2 变体、枯立木、倒木、树桩、岩石、灌木、地被
  • 候选格：树 4.2 m（每块 256 格）、草 2.2 m（每块 900 格）
  • 密度由低频噪声 × 边缘衰减调制，桦树占乔木 22%，枯立木 7%
  • 排除区：营地 16 m、营地→森林路径、陡坡（> 0.45）
  • 树冠顶点着色器风摆，相位写在实例自定义数据里，整片林子不同步

第一人称

  • 走 4.5 / 跑 7.0 / 蹲 2.2 m/s，加速度 14，空中控制 0.25，跳 4.2 m/s
  • 体力 100：冲刺 18/s、恢复 12/s、延迟 0.8 s
  • 镜头呼吸：幅度 0.02 m、侧倾 0.55°、落地 0.05 m 下沉（只动相机，不动碰撞体）
  • 手电 100 电量、1.5/s 消耗；蹲下换胶囊体并压低视点
  • 启动时主动抢一次窗口焦点，失焦时 HUD 给出「点击游戏窗口继续」

弓箭

  • 右键瞄准：视野 75° → 55°，灵敏度 ×0.45
  • 左键蓄力 1.1 s 封顶，0.18 s 以下不发射；伤害 32，箭速 16→42 m/s
  • 重力 9.8、存活 25 s、命中后钉住 6 s；逐帧射线判定，弱点 ×2
  • 蓄力持续耗体力 14/s；体力低于 30% 蓄力变慢，耗尽则完全蓄不满
  • 发射产生 1.2 s 噪音，会把狼引过来

敌人

  • 林狼：55 生命、视距 24 m、听觉 22 m、伤害 9、攻击距离 1.9 m
  • 分层状态机：感知 / 决策 / 动作 / 状态，子类只覆盖钩子
  • 狼群示警、侧翼包抄、畏惧火光（排斥力场）
  • 场景里 3 只，稳定 ID wolf_01..03，掉落 2 支箭
  • 贴地改为鸭子类型调用 height_at，不再依赖已删除的 ProcTerrain

任务、存档与工具链

  • 三阶段主任务：拾取保险丝 → 装进营地无线电 → 回营火
  • 存档 3 槽、v1、JSON、原子写 + .bak、逐级迁移

03

分块世界拆解：一处做对了，三处要盯住

这一节把新世界系统的参数、预算、确定性与存档一次讲清。数据来自 chunked_world.gd、world_chunk.gd、terrain_field.gd 的常量与 docs/technical-design.md §5.1 的实测表。

参数值含义 / 后果
world_size1,024 m1,048,576 m²；_grid = round(1024 / 64) = 16 → 256 块铺满
chunk_size64 m区块边长；跨一圈 = 走 64 m
terrain_resolution32 段33×33 = 1,089 顶点、2,048 三角面、格距 2.0 m；额外采一圈算外法线（35×35 高度缓存）
terrain_radius_chunks7 圈加载上界 (2×7+1)² = 225 块；超过 7 圈即卸载
collision_radius_chunks2 圈25 块凹多边形碰撞（ConcavePolygonShape3D，layer 1 / mask 0），进出圈即建/删
vegetation 半径2 / 5 圈2 圈内满配（含地被），3–5 圈只留乔木，5 圈外不生成
build_budget_ms3.0 ms地形与植被共享的软预算；碰撞队列不走这条预算
initial_radius_chunks3 圈启动时同步建 49 块地形 + 25 块碰撞，再开始分帧
每帧上限2 + 1 + 1最多 2 块地形 + 1 块植被 + 1 块碰撞；预算检查发生在建完之后，所以 3 ms 是软上限

做对的一件事：接缝在结构上不可能裂

整片区域只有一个高度函数 TerrainField.height_at(x, z)。相邻区块在边界顶点上采样的是同一个世界坐标，所以高度必然相同；每块外扩一圈采样，相邻块的法线也由同一组点算出。地形网格、碰撞体、植被落地、玩家与敌人贴地走的都是这一个函数——不需要缝合网格，也没有边界遮罩。这条选择把「分块」从几何问题降级成了调度问题，是本轮架构上最值钱的决定。

要盯住的第一处：碰撞队列会卡死

_refresh() 每次都 _collision_queue.clear()（:214），但 chunk.collision_pending 只在 _pump() 真正取出任务时才复位（:254）。如果一次刷新排了 ≥2 个碰撞任务、而 0.5 s 的定时刷新先到，被清掉的那些块就永远带着 collision_pending = true，再也不会重新入队（:231 只在 not pending 时排队）——那块地形直到卸载都没有碰撞，走进去就是掉出世界。帧率越低越容易触发。

确定性怎么保证

  • 种子链：ChunkedWorld.world_seed（默认 20261117）→ TerrainField → GameState.world_seed → 存档
  • 区块 RNG：seed ^ (x·73856093) ^ (y·19349663)，与加载顺序、方向无关
  • 噪声始终按绝对世界坐标采样，不随区块平移
  • 同一区块卸载后重建，逐实例一致（测试有断言）

存档只写「种子 + 改动」

  • world.chunked_world = {seed, {"x,z": {...}}}，稀疏字典
  • 同种子读档 = 直接重建；不同种子 = 整世界换图
  • 但 apply_override 只解释 no_vegetation 一个键，注释里的「地形被挖开」没有实现
  • 改动表只增不删，也不带种子戳：换种子后旧改动会被套到新地形上

另外两处要盯住 ① 接缝重复候选格。区块 A 的候选格区间是 range(x0, x1+1) 闭区间，而 x1 = floor((org.x+64)/4.2) 正好等于相邻区块 B 的 x0——边界那一列/行会被两块各处理一次，两块 RNG 不同、抖动不同，于是接缝附近出现成对多出来的树/草，与注释「一格只归属一个区块」相反。
② band = -1 语义重载 + 世界中心硬编码。-1 既是「没生成过」又是「太远」，于是「曾经靠近过又走远」的块重建后仍保留稀疏乔木；而营地压平、营地染色、营地清树全按 (0,0) 判定，与 world_size 无关；CampArea 触发盒是 40×40（半对角 28.3 m），清树半径只有 16 m，四个角里是可以长树的。

这一节的判断

上一版说「文档需要的不是重写，而是半天时间的一次回写」。这一轮证明回写是可行的：technical-design §5.1 与 first-scene §7 都改得很彻底，不是打补丁，而是把实现事实写成了新的设计依据。但也要看清它的性质——这两篇都是本轮改动的顺手产物，而不是「有意识做了一次同步」。证据就是：本轮没碰的 game-design.md，三处 P0/P1 矛盾原样躺着。

所以现在的状态不是「两套事实」，而是「一半两层」：世界与场景结构已经只有一套事实，玩法与内容仍是两层。剩下的 5 篇回写不需要两天，大约两小时——把主武器、状态表、主线物品流、区域清单、版本号这五件事按代码改掉即可。

只列能在代码或运行日志里直接指认的问题，按「会不会让玩家卡住」排序。带 新 的是本轮新增或新发现的。

级别问题证据与影响
P0 敌人状态不入档
未修		 EnemyBase.get_persistent_state() / apply_persistent_state() 依然没有调用方：main.gd:103-111 只注册了 current_scene / player / inventory / world 四个提供者。读档后被打死的 3 只狼全部复活，而它们掉落的箭还带着「已拾取」状态——存档里留下孤儿键。违反 combat-and-progression §9 与 M2 退出条件。
P0 玩家死亡没有出口
未修		 player.gd:322-323 血量归零只 player_died.emit()，_on_died() 禁用控制 + 显示鼠标；没有死亡 UI、重生、读档或结算。跌落伤害（>3 m，12 HP/m）与狼的撕咬都真实生效——血条见底后游戏进入不可操作、不可恢复的软锁，只有 F9 快速读档能救。
P1 地形碰撞可能永远不生成
新		 见第 03 节的机制：_refresh() 清空碰撞队列但不清 collision_pending（chunked_world.gd:214 vs :254），被清掉任务的区块此后永不重新入队（:231 只在 not pending 时排）。结果是该区块 has_collision() == false 且没人再管它，走进该块会掉出地形。帧率低、快速跨块（瞬移、读档跳位、bench 那种大步移动）时最容易触发。修法：刷新时按坐标复位 pending，或让队列任务带版本号。
P1 冒烟测试 37.5% 概率红
新		 155 项里固定两项失败：箭矢命中林狼造成伤害（55 → 55）、普通伤害按弓的基础伤害结算。根因不是命中判定坏了：测试从狼脚下 0.45 m 处、正南 4 m 水平射一支合成箭（test_smoke.gd:497-502），而狼在之前的区块测试里已被重新唤醒（:189-190）、自行巡逻/追击了几秒，直到开火前才冻结（:493）。狼只要停在营地北侧山脊或那根倒木后方，首帧射线就先命中 layer 1 静态几何，箭被钉住，狼一滴血不掉。
[PROBE] pre-ray 1|8 = { "collider": TerrainBody, "position": (4.70, -0.74, -27.12) } ← 狼在 z=-24.57，箭在 2.56 m 外被地形挡住 [PROBE] arrow spawned vel=(0,0,42) → after40 valid=true pos=(4.70,-0.74,-27.19) hp=55.0 [MIN] wolf=(4.81,-1.18,-24.61) → hp 55→55（必失败） [MIN] wolf=(0,0,0)（营地平地） → hp 55→23（必命中）
同一个位置必失败、换平地必命中；失败时区块 loaded=true collision=true pending=false，所以「地形没建好」的假设不成立。这是测试没有控制条件，不是游戏 bug——但它让「测试全绿」这个信号彻底失效。工作区里已有修法（八方向采样地形、挑一条干净弹道），实测 3 轮全过，详见第 00 节的说明。
P1 林狼的追击逻辑仍是错的
未修		 三处叠加，数值比上一版更窄：① SUSPICIOUS → CHASE 要求距离 ≤ attack_range = 1.9 m（enemy_base.gd:199），也就是看见 24 m 外的玩家只会「走过来看看」，贴到 1.9 m 才开打；② 放弃条件写成 distance > sight_range + chase_memory（:210），26 m 与 6 s 量纲相加；③ leash_radius = 28 声明后全文无引用（:72），离家再远也不返回。
P1 音频与天气仍是空壳
未修		 WorldAudio 就绪日志仍是 zones: 0——17 个 .tscn 里没有任何 AudioStreamPlayer；WeatherController.set_weather() 除定义处（weather_controller.gd:32）之外零调用。这两项恰恰是文档里承载「用声音和天气引导探索」的手段（§8.2、§6.4）。
P1 设置读了但不生效
未修		 SettingsManager.field_of_view 与 master_volume 从 settings.cfg 读入后，全工程没有任何消费者（引用只出现在 settings_manager.gd 自己内部）：相机 FOV 固定 75，音量只在调用 setter 那一刻生效，重启即静默丢失。
P2 举弓构图过大
新		 aim_view_offset = (-0.40, -0.10, -1.15) 与 aim_fov = 55 组合下，弓几乎占满左半屏、上下弓梢出画（见第 02 节截图）。垂弓态正常，说明是瞄准偏移/缩放没跟着 FOV 收窄重算。不是功能缺陷，但在「第一人称冷兵器」里权重很高。
P2 接缝重复植被
新		 候选格闭区间 + 相邻块 x0 == x1（world_chunk.gd:268-274、:328-333）→ 边界那一列/行被两块各撒一次。每块边界约 33 个树格 + 更多草格重复参与，接缝附近会出现成对多出来的植被。与 world_chunk.gd:8-10 注释「一格只归属一个区块」相反。
P2 世界中心硬编码 + 营地排除区偏小
新		 营地压平/染色/清树都按 (0,0) 判定，与 world_size 无关（terrain_field.gd:126,175-178、world_chunk.gd:397）；CampArea 触发盒 40×40（半对角 28.3 m）而清树半径 16 m（world_chunk.gd:28），四个角里能长树。
P2 探针脚本留在仓库里
新		 _probe_arrow.*、_probe_bow.* 已被跟踪且写着「用完即删」，没有任何测试引用；_probe_focus.* 已在暂存区删除（提交即可）；工作区还有一个未跟踪的 _probe_shot.*。建议统一挪到 .gitignore 或 tools/probes/。
P2 存档改动表只增不删
新		 GameState.chunk_modifications 没有修剪、没有种子戳（game_state.gd:57-75）；换种子后旧坐标的改动会被套到新地形上；apply_override 只解释 no_vegetation 一个键（world_chunk.gd:75-79），注释里「地形被挖开」并无实现。
P2 远景黑边
新		 雾 30→420 m（time_of_day.gd:76），天空下半球 ground_horizon_color = 0.12,0.15,0.12（:108-109）。从高处或长焦看出去，地形边缘外是黑色空档（第 02 节首图）。地面视角看不见，所以优先级低。
P2 测试套件顺序耦合
加重		 155 项跑在同一个场景、同一个进程、共享 _player/_inventory/_quest_manager：第一人称用例真射一箭（-1 支）、背包用例 +5/-2 支、战斗用例杀狼并拾取掉落、存档用例把「狼已死、箭已捡」写进 slot 0、迁移用例依赖 slot 2、备份用例依赖前面的 slot 0。任何一项单独跑都过不了——这也是第 3 条那种 flake 能被掩盖的原因。

弓箭无限制

裁决日期 2026-11-17 · 影响玩法与 5 个文件
裁决
箭矢不作为资源：射击不消耗、不需要拾取、HUD 不显示余量。玩家永远有箭。
代码现状
仍是扣箭制：每次发射先 has_item 再 remove_item（bow.gd:292-297）；初始装备 12 支（main.gd:24）；HUD 右下角显示「箭矢 N」（hud.gd:368-370）；林狼死亡掉 2 支；测试断言「≥10 支」。
要改哪里
① bow.gd _release_and_fire()：删掉 has_item 检查与 remove_item 调用（失败分支里的 fire_failed.emit("没有箭矢了") 一并删除）；② main.gd STARTING_GEAR 去掉 arrow: 12；③ hud.gd _on_ammo_changed 改为显示「箭矢 ∞」或隐藏该行；④ 狼的掉落改成别的（皮/肉/线索）或干脆不掉；⑤ README.md 战斗表与 test_smoke 的箭数断言同步。
平衡代价
无限制不等于无代价：蓄力 14/s 的体力消耗、1.1 s 蓄满、1.2 s 噪音暴露位置，已经构成节奏约束。若实测太顺，应该调射速、扩散、体力消耗，而不是回到弹药计数——弹药计数只会让玩家在营地里捡垃圾。
连带影响
arrow.tres 可保留（靶场教学、未来投掷物），但不再进初始背包；存档里的 inventory 字段自然不再含箭；「掉落物可拾取」这条测试需要换一件物品。

完成度与下一步

里程碑按 development-plan.md 原定义评估。M0、M1 完成；M2 从「约 30%」推进到「约 45%」——涨的是世界与表现，不是内容。

  1. M0 · 工程基础已完成

    Godot 4.6 工程、输入映射、结构化日志、第一人称原型、一键启动与构建脚本。本轮新增 toggle_help 动作与窗口抢焦点，基础设施仍在往前走。

    退出：开发构建可启动；键鼠移动 / 暂停 / 退出正常；错误写入 user://logs/game.log。
  2. M1 · 灰盒可玩链路已完成有自动化验证

    营地灰盒、交互、物品、背包、任务、存档端到端打通。遗留仍是敌人状态不入档——不影响三步链路，但阻塞 M2。

    退出：营地出发—拾取保险丝—修复无线电—返回营火可完整游玩；读档恢复关键状态。
  3. M2 · 探索与战斗垂直切片约 45%世界已达标

    已做：1 km² 分块世界与流式加载、弓箭完整链路、一类敌人、昼夜、程序化天空与雾。未做：第二类敌人、两个世界事件、隐藏地点、天气切换、音频、设置菜单、地图 / 指南针、20–30 分钟内容量。

    差距从「世界不够大」变成了「世界里没事可做」：可玩内容仍是营地那 90 秒的三步循环，1 km² 目前是背景。
  4. M3 · 程序化森林管线未启动

    SceneSpec / Blender / GLB / manifest 全部空白。不过世界系统已经是「种子 + 全局函数 + 分块」的确定性结构，这正是 AI 生成管线要接的形状——先接哪一头，现在比上一版更清楚了。

出生点、物资箱、无线电、营火全在 10 m 半径内，三次交互通关。「~3 min」是加上走到溪谷、山脊、靶场再回来的散步时间——多了一圈可走的地方，没有多一件事可做。

这一版最该守住的三条

  • 单一高度真相：只要 height_at 不动，世界再大也不会撕裂。任何「局部地形微调」需求都应该先问：能不能表达成这个函数的一部分？
  • 预算化的加载：地形/植被排队 + 3 ms 预算，让 225 块地形不至于在第 1 帧全部落地。下一步要补的是把碰撞也纳入预算，并修掉第 05 节的 pending 卡死。
  • 随手回写文档：本轮两篇文档改得好，恰恰因为改的人当时就在改那块代码。把它变成习惯，比排一次「文档日」有效。

一句话判断

地基已经够用了，现在最危险的动作是继续扩地基。下一步的性价比排序很清楚：先把「会随机红的测试」和「会掉出世界的碰撞」这两个确定性问题修掉（半天），再把上一版的两条 P0 补上（一天），最后才谈内容；而弓箭无限制这一条，30 分钟就能落地，且能让战斗手感立刻少一层摩擦。
